Mirrors designs/stitch/segments-builder.png in brand tokens: a two-column layout — the visual filter-group builder (left) and a live matching-count + sample-contact preview (right). The builder is an Alpine component over the FROZEN filter shape (survey-schema.json#/$defs/segmentFilter / apps.segments.filters): a root group {connector, conditions:[…]} whose conditions are either leaves {attributeKey, operator, value?} or one level of nested groups. The UI caps nesting at depth-2 (the mockup's shape); the validator accepts up to depth 64, so this is a UI simplification, not a data-model cap. On every change the assembled filter JSON is POSTed to the preview endpoint (HTMX, debounced) which validates + previews via the real segment-eval service; the same JSON is written into a hidden field for save.
